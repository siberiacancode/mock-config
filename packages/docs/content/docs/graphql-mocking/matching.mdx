---
title: Matching
description: How Mock Config matches GraphQL operations to handlers.
---

When a GraphQL request arrives, Mock Config matches it against registered handlers by checking three things in order: the **full query document**, the **operation name**, and the **event name**. The first handler whose identifier satisfies any of these checks wins.

## Query

The identifier is compared against the normalized full query string sent by the client. This lets you match an operation by its exact shape, regardless of what name it was given.

```ts
graphql.query(
  `query GetUsers {
    users {
      id
      name
    }
  }`,
  { data: { users: [] } }
);
```

Incoming queries are normalized before comparison (whitespace and ignored characters stripped), so formatting differences do not affect matching.

## Operation Name

The identifier is compared against the `operationName` field of the request — the name declared after `query`, `mutation`, or `subscription` in the document.

```ts
graphql.query('GetUsers', { data: { users: [] } });
```

For the query:

```graphql
query GetUsers {
  users {
    id
    name
  }
}
```

The operation name is `GetUsers`.

## Event Name

The identifier is compared against the first field in the operation's selection set. This is called the **event name**.

```ts
graphql.query('users', { data: { users: [] } });
```

For the same query:

```graphql
query GetUsers {
  users {
    id
    name
  }
}
```

The event name is `users` — the first selected field.

This is useful when operations are sent without an explicit `operationName`, or when you want to match multiple differently-named queries that all fetch the same field.

## Regular Expressions

A RegExp identifier is tested against all three values — query, operation name, and event name — in order. The handler matches if the expression satisfies any of them.

```ts
//[JAVA_COMMENT_REDACTED_b16e2a71]
graphql.query(/^Get/, { data: {} });

//[JAVA_COMMENT_REDACTED_47d8b591]
graphql.query(/users/, { data: { users: [] } });
```

## Match Order

When multiple handlers match the same operation, Mock Config picks the most specific one based on weight. A string identifier is always considered more specific than a RegExp. Among handlers with the same specificity, the one declared first is preferred.

## Summary

| What is checked          | String identifier        | RegExp identifier        |
| ------------------------ | ------------------------ | ------------------------ |
| Full query document      | exact match (normalized) | `.test(normalizedQuery)` |
| Operation name           | exact match              | `.test(operationName)`   |
| Event name (first field) | exact match              | `.test(eventName)`       |
